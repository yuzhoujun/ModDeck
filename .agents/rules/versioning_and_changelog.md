# ModDeck 版本规范与更新日志记忆规则

## 1. 版本号命名规范（严格遵循 SemVer）
软件内（`package.json`、`appVersion` 等）严禁出现 `-test` 等随意后缀，严格遵循语义化版本：

1. **正式发布版本（Release / Tag）**：
   - 格式：`x.y.0`（如 `2.1.0`、`2.2.0`、`2.3.0`）
   - 规则：大版本与小版本在 GitHub 发布正式 Release 与 Git Tag。

2. **本地测试版本（Test / Milestone）**：
   - 格式：`x.y.z`（如 `2.2.1`、`2.2.2`、`2.2.3`、`2.2.4`）
   - 规则：仅在本地构建、测试验证，不单独在 GitHub 打 Release Tag。

3. **测试阶段的修复/优化补丁版本（Patch）**：
   - 格式：`x.y.z-patch.N`（如 `2.2.4-patch.1`、`2.2.4-patch.2`）
   - 说明：口头交流和提交信息中可称为 `2.2.4.1`，但在 `package.json` 中统一记录为 `2.2.4-patch.1`，符合 SemVer 标准且杜绝 `-test` 这种非标后缀。

## 2. 更新日志（CHANGELOG.md）书写规范

1. **条目合并归纳原则**：
   - 修复优化版本（如 `2.2.4.1`、`2.2.1.1`）**不单独开辟二级标题**，而是必须合并归纳在所属的测试版本（如 `2.2.4`、`2.2.1`）条目中。

2. **标题格式**：
   - 若测试版本包含后续修复版本，**标题必须完整列出所含的修复版本号**：
     - 正确范例：`## 2.2.4（本地测试，含 2.2.4.1 修复优化）`
     - 正确范例：`## 2.2.2（本地测试，含 2.2.2.1 / 2.2.2.2 / 2.2.2.3 / 2.2.2.4 修复优化）`
     - 正确范例：`## 2.2.1（本地测试，含 2.2.1.1 修复优化）`
   - 若测试版本无后续单独补丁，标题为：
     - `## 2.2.3（本地测试）`

3. **内容层级**：
   - 测试版本条目内部，针对具体的补丁优化使用明确的子级说明：
     - 如 `- **2.2.4.1 重载开关三向细分与多角色预设聚合队列 (Pending Preset Queue)**：...`
     - 如 `- **2.2.1.1 默认变体快照、覆盖保护与本地优先说明**：...`
